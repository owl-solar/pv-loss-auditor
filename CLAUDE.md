# PV Loss Auditor

Portfolio project for Solar Performance / Asset Performance Engineer roles.
Diagnoses underperformance of a PV plant: compares actual generation with
weather-corrected expected generation, computes plant KPIs and breaks losses
down by cause into a loss waterfall in kWh and EUR.

This is project 1 of a chain:
1. **PV Loss Auditor** (this repo) – find losses
2. Repowering Planner – decide what to do (NPV / IRR / LCOE of scenarios), uses outputs of this repo
3. O&M Copilot – RAG assistant for alarm codes and manuals

## Data
- **NREL PVDAQ** via OEDI public S3 bucket (`oedi-data-lake/pvdaq`) + its metadata file.
  Selection criteria: ≥3 years of data, POA irradiance, module temperature, AC power,
  known tilt/azimuth/DC & AC capacity; inverter-level data preferred.
- **Open-Meteo** historical weather as a satellite/reanalysis alternative to on-site sensors.
- **Electricity prices**: US market prices matching the plant's location and connection type:
  ISO day-ahead LMP (via `gridstatus`) for grid-connected plants in an ISO;
  utility/state commercial tariff (EIA) for behind-the-meter systems;
  regional wholesale estimate (EIA) for plants outside ISO regions.
  Losses reported in USD (optional EUR conversion). Document the price assumption explicitly.
- Never invent or "fill in" real measurements. Anything synthetic (e.g. injected string faults) must be generated by an explicit, documented script and labelled as synthetic everywhere.

## Analysis period
**9069: 2020-05 … 2023-11** (43 months, 5-min data). Chosen from the full-period coverage map
(`notebooks/01_data_qa.ipynb`, section "Data coverage and sensor availability",
`reports/figures/9069_data_coverage.png`; point sampling, accuracy about ±15 percentage points).
In this period, share of daylight snapshots with a valid value (mean; months below 90 %):
- AC power, inverters 01/10/30: 100 % (0 months); plant meter 2: 100 % (0 months).
  Meter 2 exists only from 2020-03-26; meter 1 has no data after 2019-04-04.
- POA reference cells 01 / 04 / 10: 98–99 % (3 / 1 / 1 months); all three ≥ 90 % in 40 of 43 months.
- Module temperature, thermocouples 01 / 03 / 06 s1 / 10: 96–99 % (3–5 months each, worst:
  tc 03 in 2020-06 at 20 %, tc 01 in 2020-12 at 57 %); ≥ 2 of the 4 are ≥ 90 % in 40 of 43 months.
- Irradiance file has 5-min steps (15-min from 2018-04 to 2020-03). Gaps > 1 day in the period,
  from the full irradiance download: 2021-12-23 → 12-25 (2.0 d) and 2022-05-20 → 05-23 (2.9 d).
  The second sampling pass of the coverage map missed the second one (point sampling cannot see
  gaps shorter than about 3 days reliably); the other files may hide similar short gaps until
  they are downloaded. No month with fewer than 3 daylight snapshots.

**Rejected: candidate 2 (2018-04 … 2023-11).** Thermocouples work at only 0–57 % per month
(typically 11–57 %) in 2018-04 … 2020-04, on all sensors at once (looks like a logger problem);
two more irradiance gaps (6 d, 12 d); meter 1 → meter 2 switch with a 357-day hole.

**What 2019 actually contains** (so it is not mistaken for an empty year): inverter AC ≈ 100 %
all year; POA reference cells 01 / 04 / 10 ≈ 100 % all year; environment file continuous, but
valid thermocouple values only 11–50 % per month (0 % in November); irradiance at 15-min steps
with gaps 2019-01-27 → 02-02 (6 d) and 2019-11-20 → 11-21 (1 d), GHI 0 % in 2019-08 … 10,
pyranometer 02B 0 % in 2019-09 … 12; meter file has **no rows** from 2019-04-04 07:00 to
2020-03-26 06:55 (357 d), meter 1 is the only meter reporting before that. The 2019 sample was
skipped only because meter, thermocouple and 5-min irradiance data are missing there.

## Constraints
- Mobile internet: minimize traffic.
- Always estimate download size and ask before any download > 100 MB.
- Never re-download data that is already cached locally.
- Prefer column-selective formats (parquet) and byte-range reads.
  (PVDAQ 9069 exists only as wide CSV; byte ranges cut time, not columns.)
- Confirmed on 2026-10-24: full download of the 9069 analysis period (2020-05 … end of files,
  4 CSV files, ≈ 1.2 GB; estimate 1 215 MB). The approval covers exactly this volume.
- Large downloads must resume month by month: save each month to parquet as soon as it is
  complete, keep a manifest, and on restart continue after the last saved month without
  re-downloading anything.

## Open questions
- Time zone of 9069 timestamps: UTC, fixed EST (UTC−5) or local time with DST? Metadata gives only
  `timezone_code: 5`. Check in Phase 1 QA (solar noon, DST jumps).
- AC rating of 9069 inverters 6–40: 825 kW is given only for inverters 1–5; 40 × 825 = 33 000 kW
  is assumed to be plant AC. Check via inverter peak power / clipping level.
- 9069 string mismatch: inverters 1–20 have 272 strings, 21–40 have 68 (× 19 modules), which gives
  implausible DC/AC 1.88 vs 0.47 at equal 825 kW; strings × modules = 129 200 vs 129 390 modules
  in the module table.
- 9069 module γ = −0.28 %/°C for the 295 W multi-Si module (typical −0.40…−0.45). Check in Phase 2.
- 9069 POA after 2022-05: class-A pyranometers are gone (02B: 0 % from 2022-06; 08: 0 % from
  2020-09; GHI pyranometer 12: 0 % from 2022-04), so PR will rely on reference cells 01 / 04 / 10.
  Reference cells and pyranometers differ in spectral and angle-of-incidence response, so check
  cell drift against pyranometer 02B over 2020-07 … 2022-04 (02B is 60–100 % there; 0 % in
  2020-05, 50 % in 2022-05) and document the result in Phase 2.
- 9069 sample files (Jun + Dec 2020) keep only the 11 channels chosen before the coverage map;
  several of them are empty in 2020 (pyranometer 02A, thermocouples 02 s2 / 08 s1, meter 1).
  Channels for the analysis period must be re-selected (reference cells, thermocouples
  01 / 03 / 06 s1 / 10, meter 2); the cached slices cannot be reused for them.

## Stack and methodological decisions
- Python, pandas, pvlib (ModelChain, temperature and inverter models), **pvanalytics** (data QA, clipping detection), **RdTools** (YoY degradation, SRR soiling), scikit-learn, plotly, Streamlit.
- KPIs: temperature-corrected Performance Ratio (IEC 61724-1 approach), specific yield, availability.
- Anomaly detection: Isolation Forest on **residuals** (actual minus pvlib model), not on raw power.
- Compare PR computed with on-site POA vs Open-Meteo irradiance and discuss the difference.

- Logic lives in `src/`; notebooks call it and show results and conclusions.

- Small, descriptive git commits per step.
- Code, comments and README in English (international employers).
